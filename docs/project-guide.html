01 / Apa yang dilakukan project ini?

Aplikasi menyimpan daftar akun Instagram yang ingin dipantau, mengambil profil serta metrik postingannya, lalu menampilkan hasil melalui dashboard lokal. Python bertugas mengambil data; Next.js menyediakan tampilan dan API; PostgreSQL menyimpan hasilnya.

Tambah target→Jalankan scraper→Simpan database→Lihat dashboard
Scraping berjalan satu batch sampai target selesai. Tidak ada scheduler yang otomatis mengulang batch. Request status dari browser tetap berjalan setiap 2 detik selama halaman terbuka.

03 / Metode scraping

Project mengambil data melalui pemanggilan API oleh library instagrapi menggunakan sesi akun Instagram. Kode tidak membuka browser otomatis dengan Selenium/Playwright dan tidak mem-parsing HTML halaman dengan BeautifulSoup. Ini juga bukan integrasi Graph API resmi dengan access token aplikasi.

Autentikasi berbasis session

get_sessionid() membaca INSTAGRAM_SESSIONID dari environment. Jika kosong, kode mencoba membaca cookie SQLite Zen Browser dari path Linux yang sudah ditentukan. Kemudian login_by_sessionid() dipakai untuk login. Pada Windows, gunakan konfigurasi session di .env.

Phase 1 — profil dan postingan

  1. Cari Instagram user ID di cache tabel profiles. Jika belum tersedia, panggil user_id_from_username().
  2. Panggil user_info(), lalu simpan profil. Jika akun private, kode melewati pengambilan postingan.
  3. Panggil user_medias(user_id, amount=0). Kode tidak menetapkan batas jumlah postingan; pengambilan dapat melibatkan banyak halaman/request sesuai respons library.
  4. Klasifikasikan media sebagai post, carousel, reel, atau video. Simpan URL, tanggal, likes, jumlah komentar, dan caption maksimal 500 karakter.
  5. Perbarui last_scraped_at, lalu tunggu 55–120 detik sebelum akun berikutnya.

Phase 2 — metrik video

Ambil reel/video milik target aktif dari database, lalu panggil media_info(media_pk) untuk setiap item. Nilai views berasal dari play_count, lalu view_count, lalu 0 jika keduanya kosong/nol. Simpan juga durasi dan informasi audio. Jeda antaritem 2–4 detik.

Nama fungsi get_reels_without_views() bisa membingungkan: query saat ini mengambil semua reel/video target aktif yang punya media_pk, termasuk yang sudah memiliki views. Phase 2 bisa dipakai untuk memperbarui views.

Data disimpan memakai INSERT ... ON CONFLICT ... DO UPDATE: profil dicocokkan berdasarkan username dan postingan berdasarkan shortcode. Pengambilan ulang memperbarui sebagian kolom pada baris yang sama. Project menyimpan metrik, bukan mengunduh file foto/video atau isi komentar.

Jumlah request tidak dijamin hanya tiga per akun. Pagination, perilaku library, dan jumlah postingan memengaruhi durasi. Jeda tidak menjamin terhindar dari pembatasan Instagram.

04 / Alur eksekusi kode

  1. Dashboard dimuat: browser meminta daftar target, postingan, dan status melalui API lokal.
  2. Tambah username: POST /api/targets membersihkan input dan menambahkan target. Username yang sudah ada dilewati.
  3. Klik scrape: browser mengirim POST /api/scrape. UI saat ini hanya mengirim username; API memakai default mode phase1.
  4. API menjalankan Python: Node.js memakai child_process.spawn untuk menjalankan venv/Scripts/python.exe dan scraper.py di Windows.
  5. Python mulai: main() membuat InstagramScraper, membuka koneksi database, login Instagram, lalu memilih mode dari argumen CLI.
  6. Proses batch: scraper mengambil data, menyimpan SQL, dan menulis perkembangan ke scrape_status.json.
  7. Browser memantau: GET /api/scrape setiap 2 detik membaca status; request ini tidak memulai scraping baru.
  8. Proses berakhir: handler close di API menandai proses selesai. Dashboard dapat memuat ulang data dari database.
Jalankan hanya satu scraper sekaligus. Pencegahan proses ganda pada API menggunakan variabel memori proses Node.js; itu bukan lock global dan tidak melindungi dari scraper CLI terpisah.

05 / Langkah menjalankan project

Setup database dan dependency sudah dilakukan pada mesin ini. Untuk penggunaan harian, mulai dari memastikan PostgreSQL aktif, mengisi session, lalu menjalankan web.

1. Pastikan PostgreSQL hidup

Jalankan dari folder utama project. Jika server sudah hidup, tidak perlu start ulang.

& 'C:\Program Files\PostgreSQL\17\bin\pg_isready.exe' -h 127.0.0.1 -p 5433

# Hanya jika belum aktif:
& 'C:\Program Files\PostgreSQL\17\bin\pg_ctl.exe' -D .local/pgdata -l .local/postgres.log -o '-h 127.0.0.1 -p 5433' -w start

2. Periksa konfigurasi

Python membaca .env di folder utama. Next.js membaca web/.env.local. Samakan pengaturan PG pada kedua file.

PGHOST=127.0.0.1
PGPORT=5433
PGDATABASE=ins_loader
PGUSER=instagram_app
PGPASSWORD=isi_password_lokal_yang_sudah_dibuat

Password asli tersedia pada file konfigurasi lokal, sengaja tidak disalin ke dokumentasi ini.

3. Isi session Instagram pada .env utama

  1. Login Instagram di browser.
  2. Buka Developer Tools (F12), lalu Storage atau Application.
  3. Buka Cookies untuk instagram.com dan cari nama sessionid.
  4. Salin hanya nilainya ke konfigurasi berikut.
INSTAGRAM_SESSIONID=nilai_cookie_sessionid

Session adalah kredensial akses akun; simpan hanya secara lokal. Jika session kedaluwarsa, isi ulang dengan session yang valid.

4. Jalankan dashboard

cd web
npm run dev

Buka http://localhost:3000. Biarkan terminal ini berjalan.

5. Tambah target dan jalankan Phase 1

Masukkan username target melalui dashboard, lalu klik scrape. API otomatis menjalankan Python. Tunggu sampai semua target selesai; jeda antar akun adalah bagian normal dari proses.

6. Ambil views bila diperlukan

Setelah Phase 1 selesai, buka terminal kedua pada folder utama project:

.\venv\Scripts\python.exe scraper.py phase2

Refresh dashboard setelah CLI selesai untuk melihat hasil terbaru. Status is_running di web hanya melacak proses yang dimulai oleh API, sehingga tidak dapat diandalkan untuk proses CLI.

Jika memasang pada mesin baru

Pasang Python, Node.js, dan PostgreSQL terlebih dahulu. Buat database serta role pemilik, lalu terapkan database/schema.sql sebagai pemilik database. Salin .env.example ke .env dan web/.env.local, sesuaikan kredensialnya. Folder .local/pgdata tidak ikut Git dan harus dibuat sendiri bila ingin memakai cluster terpisah seperti mesin ini.

python -m venv venv
.\venv\Scripts\python.exe -m pip install --use-feature=truststore -r requirements.txt
cd web
npm install

Jika npm mengalami error sertifikat pada Windows dengan Node.js 24, set $env:NODE_USE_SYSTEM_CA = '1' sebelum instalasi.

06 / Pilihan mode dan perintah

Semua perintah Python berikut dijalankan dari folder utama. Tambahkan username ke daftar target di web terlebih dahulu agar tampil pada query dashboard dan masuk pemrosesan Phase 2.

ArgumenPerilaku
phase1Proses target aktif, urut last_scraped_at dengan yang belum pernah diproses lebih dahulu.
phase2Perbarui views reel/video target aktif yang tersimpan.
fullPhase 1, tunggu 60 detik, lalu Phase 2.
retryAmbil username gagal dari file status terakhir lalu jalankan Phase 1. Bukan retry otomatis dan tidak mengulang kegagalan Phase 2 berbasis shortcode.
username1 username2Phase 1 hanya untuk username yang diberikan; tidak otomatis menambah baris targets.
.\venv\Scripts\python.exe scraper.py phase1
.\venv\Scripts\python.exe scraper.py phase2
.\venv\Scripts\python.exe scraper.py full
.\venv\Scripts\python.exe scraper.py retry
.\venv\Scripts\python.exe scraper.py username1 username2

Pilih salah satu perintah sesuai kebutuhan, jangan jalankan semua sekaligus. Tanpa argumen, scraper menjalankan Phase 1.

Menghentikan proses

Gunakan tombol Stop untuk scraper yang dimulai lewat web. Untuk CLI atau server web di terminal, gunakan Ctrl+C. Menghentikan web tidak harus menghentikan PostgreSQL.

# Hanya jika ingin mematikan database juga:
& 'C:\Program Files\PostgreSQL\17\bin\pg_ctl.exe' -D .local/pgdata -m fast -w stop

08 / Membaca status dan mengatasi masalah

queued berarti belum diproses, success berarti selesai, failed berisi item gagal, dan current menunjukkan item saat ini. Selama jeda, current bisa masih menunjukkan akun yang baru selesai.

GET /api/scrape terus muncul di Network

Itu polling status setiap 2 detik. Yang memulai scraping adalah POST /api/scrape. GET tidak mengambil data Instagram.

Views masih kosong

Phase 1 tidak mengambil views. Jalankan Phase 2 setelah postingan tersimpan dan pastikan target masih aktif.

Login gagal atau Zen browser cookies not found

Periksa INSTAGRAM_SESSIONID dalam .env utama. Pada Windows, fallback cookie Linux tidak akan menemukan profil browser Windows. Session tidak valid/kedaluwarsa perlu diganti.

Database error atau connection refused

Periksa apakah PostgreSQL menerima koneksi di port 5433. Samakan PGHOST, PGPORT, PGUSER, PGPASSWORD, dan PGDATABASE pada konfigurasi Python serta web. Pastikan schema sudah diterapkan.

Data hasil CLI tidak terlihat di dashboard

Query postingan memakai JOIN ke targets. Username yang diberikan langsung lewat CLI tidak otomatis menjadi target. Tambahkan username tersebut di web dan periksa filter target aktif.

Rate limit atau proses terasa lama

Jumlah postingan tidak dibatasi oleh kode. Phase 1 juga menunggu 55–120 detik antar akun. Ketika terkena PleaseWaitFewMinutes, Phase 1 mencatat kegagalan; Phase 2 berhenti. Konstanta DELAY_ON_RATE_LIMIT = 120 ada tetapi belum digunakan untuk mekanisme tunggu/retry otomatis.

Status CLI dan dashboard berbeda

API menyimpan handle proses pada memori Node.js. Proses Python yang dimulai manual tidak tercatat pada handle tersebut. Untuk CLI, terminal adalah acuan status proses; hindari memulai batch kedua dari web.
